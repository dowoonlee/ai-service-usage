## 목표와 적용 범위

기존 펫, 6타입 상성, 스킬, 상태이상, 궁극기를 사용해 유저가 기술과 교체를 직접 선택하는 전투를 추가합니다. 새로운 수집 시스템이나 별도 게임을 만들기보다, 이미 가진 팀을 직접 지휘하는 경험을 목표로 합니다.

핵심 판단은 세 가지입니다. 지금 피해를 줄지 효과를 준비할지, 불리한 상대 앞에서 버틸지 교체할지, 궁극기를 지금 쓸지 남길지를 선택합니다. 전투 후에는 자신의 선택과 결과를 연결해서 이해할 수 있어야 합니다.

첫 적용 지점은 기존 아레나의 연습전입니다. 같은 화면에서 `직접 조작`과 `자동 관전`을 선택합니다. 기존 자동 ATB 랭크전, 강화 경제, 시즌 보상, 관장 클리어 조건은 이번 초안으로 변경하지 않습니다. 수동 연습전이 재미 검증을 통과하면 관장 체험과 서버 수동 도전으로 확장합니다. 실시간 유저 대 유저 대전은 범위 밖입니다.

포켓몬 골드에서 참고하는 것은 명령 선택, 교체의 비용, 선후공 판단입니다. 타입 수, 스킬 이름, 펫, 궁극기는 AIUsage의 것을 유지합니다. 골드의 세부 규칙을 그대로 복제하는 설계는 아닙니다. 골드·실버의 우선도와 스피드 규칙은 [Smogon 설명](https://www.smogon.com/gs/articles/move_priority)을 참고했습니다.

## 기존 구현에서 재사용할 부분

| 현재 코드 | 확인한 동작 | 수동전에서의 처리 |
|---|---|---|
| `PetBattleStats.swift` | HP·ATK·DEF·SPD, 희귀도·강화·이로치·개체 프로필 | 파생 스탯 계산 재사용, 전투 시작 때 동결 |
| `PetSkills.swift` | 기본기, 타입기, 컬렉션기, 고유기, 궁극기 | ID·명칭·타입·효과 배정 재사용, 별도 수동전 정책 적용 |
| `PetSynergy.swift` | 같은 컬렉션·타입 시너지, 컬렉션 간 상성 | 관계는 유지, 수동전 시너지 크기만 제한하는 안을 검증 |
| `BattleEngine.swift` | SPD 비례 ATB, 전체 경기 일괄 계산, 자동 스킬 선택 | 기존 엔진 유지, 단계 진행형 수동 엔진 추가 |
| `BattleReplayView.swift` | 확정 로그로 HP·출전 펫 재구성 | 무대·HP·펫 연출을 공유 컴포넌트로 추출 |
| `ArenaView.swift` | 편성, 연습전, 서버 랭크전, 강화소 | 연습전 진입과 팀 편성 재사용 |
| `RankingAPI.swift`, `pvp-challenge` | 요청 한 번으로 서버가 경기 전체 확정 | 서버 수동전 단계에서 세션·명령 API 추가 |

현재 출전 펫은 배열에서 처음 살아 있는 펫으로 결정됩니다. 자유 교체를 지원하려면 `activeSlot`을 별도로 저장해야 합니다. 배열 자체를 교환하면 팀 시너지의 동률 판정까지 바뀔 수 있으므로 편성 순서는 전투 동안 고정합니다.

현재 전투 이벤트는 공격 중심이고 상태 효과는 별도 스트림입니다. 교체·방어·대기·강제 출전을 공격처럼 끼워 넣지 않고, 수동전에는 순서가 명확한 통합 이벤트를 사용합니다.

## 플레이 흐름

1. 아레나 연습전에서 직접 조작을 선택합니다.
2. 기존 편성을 불러오고 선봉, 기술, 남은 슬롯을 확인합니다. 정규 기술은 해금된 기술을 그대로 사용하고, 레인보우 펫은 궁극기 분기 하나를 선택합니다.
3. 상대의 팀 구성과 선봉을 확인하고 전투를 시작합니다. 시작 후 양 팀 스냅샷을 고정합니다.
4. 기술, 교체, 방어 중 하나를 선택합니다. 궁극기가 준비되면 기술 메뉴에 추가됩니다.
5. 양측 행동과 턴 종료 효과를 재생합니다. 다음 명령을 받을 때까지 전투가 진행됩니다.
6. 기절한 펫이 있으면 다음 출전 펫을 선택합니다.
7. 승패와 주요 선택 기록을 확인하고 같은 조건으로 재도전하거나 편성으로 돌아갑니다.

연습전은 양측 동일 인원인 1대1부터 5대5까지 허용합니다. 튜토리얼은 3대3, 일반 편성은 기존 최대 5마리를 사용합니다. 수동 서버 도전은 후속 단계에서 5대5만 허용합니다. 보유 펫이 부족한 사용자를 위해 튜토리얼에서는 고정된 대여 팀을 제공하며 소유권이나 도감을 변경하지 않습니다.

## 명령과 턴 규칙

### 선택 가능한 명령

| 명령 | 소비 | 규칙 |
|---|---|---|
| 기술 | 1행동, 해당 기술 PP | 상대 현재 출전 펫을 대상으로 사용합니다 |
| 궁극기 | 1행동, 팀 게이지 10 | 현재 출전 펫이 레인보우일 때만 선택할 수 있습니다 |
| 교체 | 1행동 | 살아 있는 다른 펫으로 바꾸며 그 턴에는 공격하지 않습니다 |
| 방어 | 1행동 | 해당 턴의 직접 피해를 50% 경감합니다 |
| 항복 | 경기 종료 | 연습전에서는 보상 없이 종료하며 서버전에서는 완료된 패배로 처리합니다 |

명령 입력 중에는 시간제한이 없습니다. 기술 선택 전까지 메뉴 간 이동과 취소가 가능합니다. 명령 확정 뒤에는 상대 행동을 본 후 바꿀 수 없습니다. 전투 중 소모품, 포획, 추가 펫 구매는 제공하지 않습니다.

### 한 턴의 처리 순서

1. **명령 대기:** 양측 출전 펫, HP, PP, 게이지, 효과가 확정된 상태입니다. 방어 AI가 이 상태만 보고 자신의 명령을 먼저 정합니다.
2. **플레이어 명령 검증:** PP, 생존 여부, 교체 대상, 게이지, 현재 상태 버전을 검사합니다. 잘못된 명령은 턴을 소모하지 않습니다.
3. **행동 순서 고정:** 교체 → 방어 → 기술 순입니다. 같은 우선도에서는 턴 시작 시 유효 SPD가 높은 쪽이 먼저이며 동속은 시드 기반 추첨입니다. 일반 기술과 궁극기의 우선도는 같습니다.
4. **명령 실행:** 실행 직전 생존·출전 여부와 행동불가를 확인합니다. 행동 가능한 경우에만 PP·게이지를 소비합니다.
5. **턴 종료 효과:** 양 팀의 모든 생존 펫에 대해 지속 효과를 처리하고 효과 기간을 갱신합니다.
6. **종료 판정:** 한쪽 전멸은 패배, 양측 전멸은 무승부입니다. 필요하면 강제 출전 단계로 이동하고, 아니면 다음 턴으로 이동합니다.

공격은 명령 확정 시의 특정 상대 슬롯을 추적하지 않습니다. 상대가 먼저 교체했다면 새 출전 펫에게 명중합니다. 선공으로 상대를 쓰러뜨리면 기절한 펫의 미실행 명령은 취소되고 PP도 소비하지 않습니다. 그 자리를 채울 펫이 같은 턴에 대신 공격하지는 않습니다.

SPD는 행동 횟수가 아니라 순서를 결정합니다. 턴 도중 SPD 버프·디버프가 생겨도 이미 정한 순서는 바뀌지 않으며 다음 턴부터 반영합니다.

### 교체와 강제 출전

자발적 교체는 공격 기회를 포기하고 새 펫이 상대 공격을 받는 선택입니다. HP와 PP는 그대로 유지됩니다. 나가는 펫의 버프·실드는 제거하고 디버프는 유지합니다. 벤치에서도 디버프의 기간과 지속 피해가 진행되므로 교체만 반복해서 독을 멈출 수 없습니다.

기절 후 강제 출전은 다음 턴 전에 수행하며 행동을 소비하지 않습니다. 상대 펫이 기절했다는 이유로 살아 있는 내 펫도 무료 교체하는 규칙은 제공하지 않습니다. 양측 출전 펫이 함께 기절했으면 AI의 다음 출전을 먼저 비공개 확정하고 유저가 고른 뒤 동시에 공개합니다. 교체 후보가 한 마리뿐이면 자동 출전합니다.

행동불가 상태에서도 교체는 가능합니다. 다만 교체한 펫의 디버프를 지우지는 않습니다. 교체로 팀 게이지가 늘거나 PP가 회복되지 않습니다.

### 방어

방어는 일반 공격과 궁극기의 직접 피해 및 광역 피해를 절반으로 줄입니다. 지속 피해와 후술할 소모전 피해는 줄이지 않으며, 공격의 부수효과도 막지 않습니다. 실드가 있다면 방어로 경감한 뒤 실드가 흡수합니다.

팀 기준 연속 턴 방어는 선택할 수 없습니다. 펫을 바꿔 연속 방어 제한을 우회할 수 없습니다. 직전 턴에 방어를 성공적으로 실행한 경우에만 제한하며, 행동불가로 방어하지 못했다면 다음 턴 선택할 수 있습니다. 방어 자체는 게이지를 생성하지 않습니다.

## 상성과 피해 계산

6타입 순환은 그대로 사용합니다.

`Machine → Beast → Chaos → Arcane → Mascot → Warrior → Machine`

화살표 방향은 유리한 상대입니다. 기술 타입이 상대 펫 타입에 유리하면 2배, 불리하면 0.5배, 그 외에는 1배입니다. 자기 타입 기술의 1.5배 보정과 컬렉션 간 상성도 유지합니다. 화면에는 타입 상성과 자기 타입 보정을 구분해서 표시합니다.

수동전의 초기 피해식은 다음과 같습니다.

```text
raw = (유효 ATK / 유효 DEF) × 기술 위력 × 타입 상성
      × 자기 타입 보정 × 컬렉션 상성 × 난수(0.90 이상 1.00 미만)
damage = max(1, round(raw × 치명타 배수 × 방어 배수))
실드에서 먼저 차감 → 남은 피해를 HP에 반영
```

궁극기의 방어 관통은 분모 계산 전에 적용합니다. 정수화는 최종 피해 단계에서 한 번 수행하며 HP 감소량은 현재 HP 이하로 제한합니다. Swift와 TypeScript가 같은 반올림을 사용하도록 명세·벡터를 공유합니다.

**수동전에서는 기존 확률 패링과 레인보우의 무작위 치명타를 끄는 것을 제안합니다.** 피해 90%를 무작위로 막는 패링은 계획한 마무리 공격을 크게 뒤집습니다. 수동전에서는 선택한 방어가 이 역할을 맡습니다. 확정 치명타 궁극기는 별도 효과로 유지합니다. 이 변경은 자동전에 적용하지 않습니다.

희귀도·강화·이로치의 스탯 보너스는 초기 실험에서 유지합니다. 동일 강화 팀 비교와 실제 보유 팀 비교를 별도로 실시해 조작의 영향과 성장 격차를 분리합니다. 수동 조작만으로 모든 성장 격차가 해소된다고 가정하지 않습니다.

팀 시너지는 시작 시 한 번 계산해 기절·교체 후에도 유지합니다. 수동전에서는 컬렉션의 전 스탯 추가 보너스를 최대 10%, 타입의 대표 스탯 추가 보너스를 최대 5%로 제한하는 안을 초기 실험값으로 사용합니다. 예를 들어 대표 스탯의 합계 배수는 최대 1.15입니다. 기존 5마리 단일 컬렉션의 큰 보너스가 다양한 타입을 편성할 이유를 압도하는지 검증하기 위한 조정입니다.

## 기술 구성과 사용 횟수

### 기존 해금 규칙

기존 해금은 유지합니다. 기본형은 기본기, variant 1은 타입기, variant 2는 컬렉션기, variant 3의 Epic 이상은 고유기, variant 4는 궁극기를 사용할 수 있습니다. 전투에서 소모한 PP는 계정 재화가 아니며 새 경기마다 복원됩니다. 전투 중 교체나 앱 재실행으로 복원되지는 않습니다.

기본형의 기술 선택이 하나뿐이라는 한계는 튜토리얼에서 대여 팀으로 보완합니다. 일반 전투에서도 방어와 교체는 누구나 사용할 수 있습니다. 실제 초보 사용자가 여전히 할 일이 부족하다면 수동전 공개 전에 기본형의 기술 접근성을 별도 결정해야 합니다. 이 초안은 기존에 확정된 이로치 해금을 묵시적으로 변경하지 않습니다.

### 수동전 전용 기술 정책

| 기술 계층 | 위력 | PP | 부수효과 | 맡는 역할 |
|---|---:|---:|---|---|
| 기본기 | 8 | 무제한 | 없음 | PP를 아끼며 공격하거나 적은 HP 마무리 |
| 타입기 | 6 | 3 | 기존 타입 효과를 확정 부여 | 즉시 피해를 포기하고 상태·실드 준비 |
| 컬렉션기 | 12 | 3 | 기존 배정과 부여 확률 유지 | 다른 타입 공격과 컬렉션 특성 |
| 고유기 | 14 | 2 | 기존 타입 rider 확률 유지 | 제한된 횟수의 강한 자기 타입 공격 |
| 궁극기 | 24 | 게이지 10 | 타입별 궁극기 효과 | 중요한 시점에 사용하는 결정적 행동 |

각 값은 자동전 카탈로그를 직접 덮어쓰지 않고 `ManualSkillPolicy`에서 해석합니다. 타입기 명칭이 여러 개여도 타입별 효과는 같습니다. 타입기의 확정 부여는 행동불가가 항상 발생한다는 뜻이 아닙니다. 예를 들어 데드락 상태는 확정으로 걸리지만 실제 행동 방해는 아래 확률 규칙을 따릅니다.

PP는 실제 기술 실행 시 1 감소합니다. 방어·실드에 피해가 줄어도 소비하며, 행동 전에 기절하거나 행동불가로 기술을 실행하지 못했다면 소비하지 않습니다. PP가 0이면 해당 버튼을 비활성화합니다. 기본기가 무제한이므로 별도의 발버둥 기술은 필요 없습니다.

### 기간과 중첩

턴 r에 부여된 지속 피해·회복은 r+1부터 발생하며, 지속 3턴이면 r+1, r+2, r+3의 종료 시점에 처리합니다. 스탯 효과와 실드는 부여 즉시 적용하고 r+3 종료 시 제거합니다. 같은 턴의 행동 순서는 이미 확정되어 있으므로 SPD 효과만 다음 턴 순서부터 영향을 줍니다.

동일 ID는 중첩하지 않습니다. 재부여하면 종료 턴을 기존 종료 턴과 새 종료 턴 중 늦은 쪽으로 갱신합니다. 실드는 현재 잔량과 새 부여량 중 큰 값으로 바꾸며 합산하지 않습니다. 서로 다른 스탯 효과는 기존처럼 곱합니다. 서로 다른 지속 피해도 함께 적용합니다.

재부여로 최초 적용 턴을 뒤로 미루지는 않습니다. 이미 적용 중인 지속 피해·회복은 그 턴에도 정상 처리하고 종료 시점만 연장합니다. 새 행동불가 부여에 면역이 적용되면 부여 확률 추첨도 생략합니다. 이 순서를 양 언어의 난수 소비 규칙으로 고정합니다.

효과 슬롯은 기존 상한 4개를 유지합니다. 초과하면 종료 턴이 가장 이른 효과를 제거하고, 동률이면 먼저 부여된 효과를 제거합니다. 피해·버프·디버프 구분 없이 같은 규칙을 적용하며 제거된 이유를 로그에 표시합니다. 남은 기간이 같을 때 사전 순서에 의존하지 않도록 부여 일련번호를 저장합니다.

턴 종료에는 각 생존 펫의 종료 직전 상태에서 지속 피해·회복량을 계산해 동시에 반영합니다. 예를 들어 HP 4에서 피해 5와 회복 6이 동시에 예정되어 있으면 HP 5로 처리합니다. 최종 HP를 0부터 최대 HP 사이로 제한한 뒤 양측 기절과 승패를 함께 판정합니다. 먼저 순회한 팀이 유리해지지 않습니다.

벤치의 디버프도 같은 시계로 만료되고 지속 피해를 받습니다. 자발적 교체 시 버프·실드는 즉시 제거하므로 벤치에서 회복을 계속 쌓을 수 없습니다. 기절한 펫은 효과가 제거되며 회복으로 부활하지 않습니다.

### 행동불가와 연속 봉쇄 방지

새 행동불가 효과는 부여한 턴의 남은 행동을 취소하지 않고 다음 턴부터 적용합니다. 확정 행동불가가 있으면 확률형보다 먼저 처리하며 두 효과가 있다고 두 번 행동을 빼앗지 않습니다. 기술·방어가 실패하면 PP·게이지는 소비하지 않습니다.

실제로 행동불가가 한 번 발생하면 그 펫은 이후 2턴 동안 추가 행동불가에 면역이 됩니다. 남아 있는 행동불가 효과는 제거하고, 면역 중에는 해당 효과를 새로 부여할 수 없습니다. 면역은 효과 슬롯을 차지하지 않으며 교체해도 유지됩니다. 디버프 해제로 제거되지 않습니다. 면역 중에도 행동불가를 동반한 공격의 피해는 받습니다.

예를 들어 5턴에 행동을 잃었다면 즉시 남은 행동불가를 지우고 7턴 종료까지 면역입니다. 피해를 주는 부수효과 기술 자체가 취소되는 것은 아닙니다. 효과 슬롯에서 밀려나거나 정화된 행동불가에는 면역을 지급하지 않습니다.

교체 명령에는 행동불가 판정을 하지 않습니다. 벤치에서 행동불가 효과가 자연 만료한 경우 실제 행동을 잃지 않았으므로 면역을 주지 않습니다. 이 규칙은 단일 효과로 여러 턴 아무것도 하지 못하는 경험을 제한하기 위한 수동전 전용 변경입니다.

## 궁극기

게이지는 개별 펫이 아닌 팀 상태로 명시합니다. 초기값은 0, 최대값과 비용은 10입니다. 교체와 기절에 관계없이 유지되며 현재 출전한 레인보우 펫의 궁극기만 사용할 수 있습니다.

한 턴에 팀이 얻는 게이지는 최대 2입니다.

- 일반 기술이 상대 HP 또는 실드에 실제 피해를 주면 +1입니다.
- 적 기술로 팀의 생존 펫이 HP 피해를 받으면 +1입니다. 광역으로 여러 마리가 맞아도 합계 +1입니다.
- 지속 피해, 소모전 피해, 교체, 방어 자체, 실드에만 흡수된 피격은 피격 충전을 주지 않습니다.
- 궁극기 사용으로 공격 충전은 얻지 않습니다. 같은 턴의 상대 공격으로 피격 충전은 얻을 수 있습니다.
- 유효한 기술 명령으로 실제 피격 후 기절해도 팀에는 피격 충전을 줍니다.

턴 시작에 게이지가 10이어야 궁극기를 선택할 수 있습니다. 그 턴에 맞아서 10이 되어도 이미 선택한 명령을 궁극기로 바꾸지 않습니다. 실제 실행 직전에 10을 소비하며, 실행 전에 쓰러지거나 행동불가이면 게이지는 유지됩니다.

| 타입 | 기존 궁극기 | 수동전 효과 |
|---|---|---|
| Beast | 커널 패닉 | 직접 대상 피해의 30%를 살아 있는 상대 벤치에 추가 피해 |
| Warrior | rm -rf --no-preserve-root | 대상 유효 DEF의 30%로 피해 계산 |
| Chaos | 전면 장애 | 다음 턴 행동불가 부여, 면역 적용 |
| Arcane | 컨텍스트 초과 | 확정 치명타 1.5배 |
| Machine | 블루 스크린 | 대상 SPD ×0.6 |
| Mascot | 전체 롤백 | 자신 최대 HP의 25% 회복 |

광역의 기준은 직접 대상의 실드·잔여 HP로 잘리기 전, 방어를 반영한 직접 피해입니다. 각 벤치의 실드로 개별 흡수하며 벤치마다 상성을 다시 곱하지 않습니다. 마무리 대상의 HP가 1이라고 광역도 1에 비례하지 않습니다. 회복은 최대 HP를 넘지 않으며 직접 대상이 기절해도 시전자가 살아 있으면 실행합니다. 적 대상 효과는 대상이 살아 있을 때만 부여합니다.

레인보우가 없는 팀도 게이지 상태는 보관하지만 사용할 수 없으므로 UI를 숨깁니다. 이는 기존 해금 규칙을 보존하는 선택이며, 대여 튜토리얼에는 레인보우를 포함해 사용 시점을 체험하게 합니다.

## 레인보우 특전인 궁극기 분기와 숙련 훈장

2026-10-25 대화에서 관심을 보인 궁극기 분기와 숙련 훈장을 구체화한 제안입니다. 두 방향을 함께 설계하되 세부 효과·수치·달성 횟수는 확정 전입니다. 대상은 이로치 조각 33개로 1회 시도하고 성공률 15%, 10번째 시도에 확정 해금하는 Prestige variant 4입니다. 33회 천장이 아닙니다.

특전의 역할은 나눕니다. 레인보우를 얻는 순간 전투 선택지가 열리고, 이후 그 펫과 쌓은 기록은 훈장으로 남습니다. 숙련 훈장을 얻어야 두 번째 궁극기가 열리는 구조는 사용하지 않습니다.

### 궁극기 두 갈래 선택

레인보우 해금 즉시 해당 타입의 궁극기 A와 B를 모두 사용할 자격을 얻습니다. 전투 전 한 가지를 장착하며 변경 비용은 없습니다. 전투 중에는 바꿀 수 없습니다. A는 기존 궁극기이고 B는 다른 상황에서 유리한 변형입니다. 상위·하위 단계나 추가 강화 단계가 아닙니다.

팀에 여러 레인보우가 있으면 각 펫이 자신의 분기를 선택합니다. 게이지는 기존 설계대로 팀 공용이므로 누구의 궁극기에 쓸지도 선택해야 합니다. 앞서 다른 아이디어로 제시한 에이스 한 마리 제한은 이 안에 도입하지 않습니다. 궁극기 사용 자격은 현재 출전 펫의 레인보우 해금과 전투 시작 스냅샷으로 결정합니다.

| 타입 | A 기존 분기 | B 변형 분기 초기안 | 선택의 차이 |
|---|---|---|---|
| Beast | 커널 패닉: 위력 24, 벤치 광역 | 집중 디버깅: 위력 30, 단일 공격, 광역 없음 | 여러 펫을 약하게 만들기 대 눈앞의 한 마리 마무리 |
| Warrior | rm -rf: 위력 24, DEF 관통 | 롤링 배포: 위력 18, 자신 방화벽 부여 | 탱커 돌파 대 공격 후 생존 준비 |
| Chaos | 전면 장애: 위력 24, 다음 턴 행동불가 | 장애 전파: 위력 16, 상대 생존 펫 전체에 최대 HP 5% 지속 피해 2턴 | 당장의 행동 방해 대 교체해도 남는 압박 |
| Arcane | 컨텍스트 초과: 위력 24, 확정 치명타 | 캐시 무효화: 상대 출전 펫의 실드를 먼저 제거한 뒤 위력 18 공격 | 일반 상대의 강한 한 방 대 실드 대응 |
| Machine | 블루 스크린: 위력 24, 상대 SPD 저하 | 세이프 모드: 위력 16, 자신 최대 HP 30% 실드 | 선후공 개입 대 현재 펫을 지키기 |
| Mascot | 전체 롤백: 위력 24, 자신 HP 25% 회복 | 체크포인트: 공격 없이 살아 있는 아군 각각 최대 HP 15% 회복 | 자신의 교환 이득 대 팀 전체 회복 |

B도 비용 10, 행동 1회, 우선도 일반 기술과 동일합니다. 신규 효과는 수동전 카탈로그에 고유 ID로 기록합니다. 기존 효과의 강도·기간을 전역 수정하지 않습니다. 예를 들어 장애 전파의 지속 피해는 별도 효과 ID, 세이프 모드는 별도 실드 ID를 사용합니다. 전투 시작 화면에서 상대의 장착 분기도 확인할 수 있습니다.

장애 전파의 공격은 현재 상대만 타격하고, 피해 처리 후 살아 있는 상대 전원에게 효과를 부여합니다. 새 효과는 다음 턴 종료부터 2회 발생하며 부수효과 자체는 게이지를 생성하지 않습니다. 커널 패닉의 즉시 광역과 구별합니다.

롤링 배포와 세이프 모드의 자버프는 공격 후 부여하고, 직접 상대가 기절해도 시전자가 살아 있으면 적용합니다. 기존 방화벽 기간과 버프 교체 제거 규칙을 따릅니다. 실드 계열은 서로 합산하지 않고 현재 잔량과 새 부여량 중 큰 값을 남기며, 동률이면 늦은 만료를 선택합니다. 두 실드를 별도 슬롯으로 쌓지 않습니다.

캐시 무효화는 현재 대상의 실드 효과만 제거하고 방어 명령·DEF 버프·행동불가 면역은 제거하지 않습니다. 방어 명령은 뒤따르는 공격 피해를 정상적으로 경감합니다. 체크포인트는 기절한 펫을 부활시키거나 디버프·PP를 회복하지 않습니다. 실제 회복량만 기록하며 전원이 만피이면 선택할 수 없습니다. 체크포인트도 궁극기이므로 공격 충전은 없으며, 자동 AI는 실제 팀 회복량을 평가합니다.

분기 선택은 저장된 파티 프리셋별로 보관하고 첫 해금 시 A를 기본값으로 둡니다. 미설정된 기존 사용자의 스냅샷도 A로 해석합니다. 기존 ATB 경기에서는 A만 사용하고 수동전의 B 장착이 자동전 로그나 결과를 바꾸지 않습니다. 같은 타입의 여러 펫도 서로 다른 분기를 장착할 수 있습니다.

### 펫별 숙련 훈장

훈장은 계정 전체가 아니라 펫 kind별로 쌓습니다. 레인보우 해금 이후 해당 펫이 실제로 활약한 승리를 기록하며, 벤치에 넣기만 한 펫에는 적립하지 않습니다. 과거 전적은 해금 시점과 참여 근거가 충분하지 않으므로 소급하지 않습니다. 이 기록은 기존 스탯 계산의 progressUnits 숙련도와 별개이며 스탯 보너스를 주지 않습니다.

| 단계 | 초기 달성 조건 | 꾸미기 보상 |
|---|---|---|
| 첫 발자국 | 유효 승리 1회 | 펫 카드의 작은 레인보우 훈장 |
| 숙련 | 유효 승리 10회 | 은색 훈장 테두리 |
| 베테랑 | 유효 승리 30회 | 금색 훈장 테두리와 펫 명찰 칭호 |
| 마스터 | 유효 승리 100회 | 홀로 훈장과 전용 승리 포즈 또는 이펙트 |

각 단계는 이전 단계를 포함한 누적 횟수입니다. 시즌이 바뀌어도 유지되며 레인보우를 외형으로 선택하지 않아도 해금 상태를 기준으로 기록합니다. 강화 실패 등 다른 경제 이벤트로 훈장을 박탈하지 않습니다. 승리 포즈를 새로 그려야 하는 경우 기존 모션에 전용 이펙트를 더하는 방식으로 먼저 제공할 수 있습니다.

유효 활약은 해당 펫이 실제 출전한 상태에서 다음 중 하나를 수행한 경우입니다. 기술로 HP·실드 피해를 줌, 실제 회복·실드·새 버프 또는 디버프를 적용함, 디버프를 정화함, 방어로 피해를 줄임, 교체로 등장해 적 기술의 피해를 받음입니다. 이미 만피인 대상의 회복, 면역인 상대의 상태 부여, 변화 없는 효과 재부여, 궁극기 메뉴 열기 등은 활약으로 세지 않습니다. 한 경기에서 펫별 최대 1승만 적립하고, 경기 도중 쓰러져도 그 전에 활약하고 팀이 승리했다면 인정합니다.

승리 단계와 별도로 두 개의 선택형 훈장 문양을 제안합니다. A 분기로 유효 궁극기를 사용한 승리 5회, B 분기로 사용한 승리 5회에 각각 문양을 주며 둘을 모두 얻으면 쌍문양을 선택할 수 있습니다. 단순 발동이 아니라 피해·회복·효과 변화가 있어야 유효 사용입니다. 마스터 승급에 양쪽 문양을 강제하지 않으므로 선호하는 분기만 사용해도 성장 기록이 이어집니다.

### 적립 대상과 출시 단계

로컬 연습, 대여 튜토리얼, 동일 조건 재도전은 훈장 진행을 미리 보여주지만 영구 기록에는 반영하지 않습니다. 무제한 재시도와 임의 팀 편성으로 공식 훈장을 채우는 구조를 피하기 위한 구분이며 결과 화면에 `연습 기록 · 훈장 미적립`을 명시합니다.

영구 훈장은 서버 수동 도전이 제공되는 단계에서 시작합니다. 여기서 무보상 베타라는 표현은 코인·RP·Elo가 없다는 뜻으로 한정하며, 훈장 기록을 활성화하는 시점은 명시적으로 안내합니다. 서버가 매칭한 경기에서 정상 전멸로 결정된 승리만 초기 적립 대상으로 합니다. 항복·만료·운영 취소·무승부는 제외합니다. 상대는 고스트이므로 다른 유저의 접속이나 자발적 패배에 의존하지 않습니다.

서버는 해금 사실과 경기의 확정 이벤트로 참여·분기 사용을 검증하고, 경기 ID와 펫 kind를 기준으로 중복 적립을 막습니다. 최종 경기 결과와 훈장 적립 근거를 같은 커밋에서 기록합니다. 장치 재설치·응답 재전송·동시 결과 조회가 추가 승리를 만들지 않습니다. 해금 사실의 서버 검증 근거가 마련되기 전에는 영구 훈장 활성화도 보류합니다.

숙련 훈장은 별도 매일 숙제나 추가 입장권을 만들지 않습니다. 후속 서버 도전의 일반 이용 한도 안에서 자연스럽게 쌓이게 하며 반복 상대 분포와 비정상 적립은 운영 지표로 관찰합니다. 최초 배포의 단계 숫자는 실제 주간 대전량을 보고 조정하되 이미 획득한 훈장은 유지합니다.

### 화면과 데이터 확장

레인보우 해금 결과에 `궁극기 두 갈래 선택 가능`을 보여주고, 펫 상세에서 A·B의 피해·효과·비용을 비교합니다. 아레나 팀 카드에는 현재 장착 분기를 작게 표시하고 전투 안에서는 장착한 궁극기 버튼 하나만 보여줍니다. 전투 중 둘 다 선택 가능한 것으로 오해하지 않도록 합니다.

훈장은 펫 상세, 팀 카드, 트레이너 카드의 대표 펫 옆에 표시합니다. 예를 들어 `베테랑 · 32승 · 마스터까지 68승`과 A·B 문양 진행을 함께 보여줍니다. 다른 펫의 실적으로 대표 펫 훈장을 표시하지 않습니다. 아레나 결과에는 실제 적립된 펫만 표시하고 서버 확정 이전에 해금 연출을 재생하지 않습니다.

수동 스냅샷에 장착 궁극기 ID와 분기 버전을, 이벤트에 실제 시전자와 궁극기 ID를 포함합니다. 훈장 집계는 계정·펫별 유효 승리, 분기별 유효 사용 승리, 달성 시각, 적립 경기 근거를 보관합니다. 전투 카탈로그 수정 후에도 이전 ID를 해석할 수 있어야 합니다.

추가 검증은 분기 변경이 진행 중 경기에 반영되지 않는지, 같은 팀의 여러 레인보우가 게이지를 중복 소비하지 않는지, 벤치·대여·항복 경기의 적립 제외, 같은 경기 중복 집계 방지, 서로 다른 계정·펫의 훈장 혼합 방지를 포함합니다. 밸런스는 A·B 전체 승률뿐 아니라 상대 팀 유형별 선택 이유와 결과를 비교합니다. B가 모든 상황에서 우월하면 강화가 아니라 분기라는 목적에 맞게 재조정합니다.

## 전투 길이와 무승부

첫 실험의 목표는 5대5에서 중앙값 15~25턴, 실제 조작 시간 3~6분입니다. 이는 측정 목표이며 현재 엔진에서 입증된 수치가 아닙니다. 단순 재생 시간보다 명령을 고민하는 시간을 함께 측정합니다.

기존 ATB의 40행동 이후 격노는 수동전에 그대로 적용하지 않습니다. 대신 25턴부터 양 팀의 모든 생존 펫이 매 턴 종료에 최대 HP 5%의 소모전 피해를 받게 하는 안을 검증합니다. 이 피해는 방어·실드를 무시하고 게이지를 채우지 않으며, 지속 피해·회복과 함께 계산합니다. 전투 시작 화면에서 규칙을 안내하고 23턴부터 경고합니다.

40턴 종료에도 양 팀이 살아 있으면 무승부로 끝냅니다. 잔여 HP 판정은 높은 HP 팀이나 회복 팀을 편향시킬 수 있어 초기안에서 사용하지 않습니다. 회복과 교체가 반복되어 상한에 도달하는 비율이 높다면 보상으로 해결하지 않고 회복량·PP·소모전 시작점을 조정합니다.

## 상대 AI와 자동 조작

### AI가 볼 수 있는 정보

첫 버전에서는 양측 팀 구성, 타입, 스킬 목록, HP, PP, 상태, 팀 게이지를 공개합니다. 상대의 이번 명령과 미래 난수는 공개하지 않습니다. 방어 AI도 플레이어의 이번 선택을 볼 수 없습니다.

AI는 명령 대기 상태가 만들어질 때 자신의 명령을 확정합니다. 플레이어가 기술 메뉴를 열거나 교체 후보를 바꾼다고 다시 계산하지 않습니다. 강제 출전 선택에도 같은 원칙을 적용합니다. 서버에서 실제 계산을 명령 수신 후 수행하더라도 입력은 저장된 턴 시작 상태로 제한하지만, 구현은 사전 확정·저장을 기본으로 합니다.

### 초기 정책

기존 `SkillCatalog.select`는 기대 피해와 버프 유무 중심이며 PP, 교체, 방어를 모릅니다. 그대로 재사용하지 않고, 합법 명령을 열거하는 별도 정책을 둡니다.

| 판단 항목 | 초기 AI 기준 |
|---|---|
| 마무리 | 확정 처치가 가능한 명령을 우선하며 가능한 경우 기본기로 PP 절약 |
| 공격 | 상성·컬렉션·실드·기대 피해·남은 PP를 평가 |
| 상태 | 이미 같은 효과가 남아 있거나 상대가 곧 기절할 때 가치 감소 |
| 회복·실드 | 실제 회복 가능량과 예상 생존 증가량을 평가 |
| 교체 | 상대가 현재 사용할 수 있는 기술들의 예상 위험과 교체 후 공격 기회를 함께 평가 |
| 방어 | 공개된 상대 궁극기 준비 상태, 다음 턴 생존 가능성 고려 |
| 궁극기 | 과잉 피해, 광역 유효 대상, 회복 가능량을 고려 |

AI는 플레이어의 가능한 명령별 예상 결과를 비교하되 실제 선택을 알아맞힌 것처럼 사용하지 않습니다. 첫 구현은 1턴 앞 평가와 명시적 점수표로 시작합니다. 가중치는 테스트에서 고정해 재현 가능하게 하고, 무조건 피해 최대화하는 단순 AI를 비교 기준으로 남깁니다. 전략 AI가 인간보다 재미있는 상대인지와 승률이 높은지는 별도 평가합니다.

자발적 AI 교체는 2턴 연속 허용하지 않는 초기 정책으로 교체 반복을 줄입니다. 이는 AI의 선택 성향이지 플레이어에게 숨겨진 전투 규칙은 아닙니다. 난이도를 위해 AI의 공격력이나 난수를 몰래 올리지 않습니다.

### 자동 기능과 기존 자동전의 구분

수동전 화면의 자동 기능은 동일한 턴제 규칙에서 내 명령만 AI에 맡깁니다. 다음 명령 대기 시점부터 켜고 끄며 진행 중인 명령을 취소하지 않습니다. UI에는 `AI에게 맡기기`로 표시해 기존 `자동 관전` ATB와 혼동하지 않게 합니다.

수동전의 자동 플레이와 직접 조작은 같은 전투 안에서 전환할 수 있지만, 기존 ATB 경기와 수동 턴제 경기를 중간에 전환하지 않습니다. AI에게 맡긴 상태에서 입력하면 다음 명령 제출 전에 멈추며, 이미 제출된 턴은 끝까지 표시합니다.

## 화면 설계

기존 포켓몬풍 대각선 무대를 재사용합니다. 상대는 오른쪽 위, 내 펫은 왼쪽 아래에 배치하고 파티·HP·상태·현재 턴을 항상 보이게 합니다. 무대 아래에는 최근 결과 한두 줄과 명령 영역을 둡니다.

```text
상대 파티  ● ● ● ○ ○                  턴 8
상대 이름  Machine     HP █████░░      상태
                                  [상대 펫]

      [내 펫]
내 이름    Warrior     HP ███░░░░      상태
내 파티    ● ● ● ● ○             궁극기 10/10

상대의 공격력이 낮아졌습니다.

[ 기술 선택 ] [ 펫 교체 ] [ 방어 ]
                        [AI에게 맡기기] [메뉴]
```

기술 메뉴는 최대 정규 4개를 2열로 표시하고 궁극기는 별도 강조 버튼으로 둡니다. 기술 이름, 타입, 위력, PP, 현재 상대 기준 상성, 효과 요약을 표시합니다. 확률형 효과에는 확률을 숨기지 않습니다. 미해금 기술은 잠금 사유를 펼쳐 볼 수 있게 하되 기본 명령 영역을 잠금 카드로 채우지 않습니다.

상세 설명에는 예상 직접 피해 범위를 표시하되, **상대가 현재 펫을 유지하고 방어하지 않을 때**의 추정임을 명시합니다. 예측 피해를 서버 확정값처럼 표시하지 않습니다. 스탯·상성·컬렉션 보정을 설명 팝오버에서 분리합니다.

교체 메뉴는 생존 여부, HP, 타입, 디버프, 기술 PP를 보여줍니다. 상성 표시는 `내 공격`과 `상대 공격`을 분리합니다. 상대가 다른 타입 기술을 사용할 수 있으므로 펫 타입만 보고 안전한 교체라고 단정하지 않습니다. `교체하면 이번 턴 공격할 수 없습니다`를 명령 확정 전에 안내합니다.

창 최소 크기 560×640에서 명령 영역을 하단에 고정하고 상단 콘텐츠만 스크롤합니다. 스킬 설명과 전체 로그는 접거나 별도 팝오버로 열어 기본 버튼을 밀어내지 않습니다. 작은 창에서는 무대 높이를 줄이고, 시트에는 명시적인 최소 높이를 둡니다.

키보드는 기술 메뉴에서 1~4, 궁극기 U, 교체 P, 방어 G, 메뉴 취소 Esc를 지원하는 안으로 시작합니다. 명령 선택과 실행 확인은 분리해 오입력을 줄입니다. 제출·연출 중에는 전투 단축키를 받지 않으며 텍스트 입력 중 전역 키를 가로채지 않습니다. 버튼에는 VoiceOver 이름과 상태를 제공하고 상성을 색상만으로 표현하지 않습니다.

배속과 연출 건너뛰기는 현재 턴 표시만 빠르게 완료합니다. 명령을 자동으로 제출하지 않습니다. 창을 숨기면 연출을 멈추고 AI 자동 제출도 멈춥니다. 이미 서버에 제출한 턴의 처리는 취소하지 않으며 복귀 시 확정 상태를 조회합니다.

## 첫 체험과 결과 피드백

첫 수동전 진입 시 3대3 대여 팀으로 세 가지 상황을 경험하게 합니다. 고정 시드와 고정 상대 정책을 사용하되 특정 답 이외의 명령도 허용합니다.

1. 자기 타입 기술과 상대 약점을 찌르는 기술을 비교합니다.
2. 불리한 출전 펫을 교체하고, 교체하면서 상대 공격을 받는 비용을 확인합니다.
3. 상태기·방어 또는 궁극기를 선택해 결과가 달라지는 상황을 체험합니다.

일반전 결과 화면은 승패, 걸린 턴, 남은 펫, 사용한 기술과 교체 횟수를 보여줍니다. 주요 장면은 `교체한 펫이 공격을 반감으로 받음`, `속도 저하 후 다음 턴 선공`, `궁극기로 두 마리 기절`처럼 로그로 확인할 수 있는 사실만 표시합니다. 반사실 시뮬레이션 없이 `이 교체 때문에 승리했습니다`라고 단정하지 않습니다.

연습전의 같은 조건 재도전은 팀·규칙·시드를 그대로 복원합니다. 행동이 바뀌면 난수 소비 순서도 바뀔 수 있으므로 모든 후속 확률 결과까지 같다고 약속하지 않습니다. 새 상대·새 시드로 시작하는 버튼도 별도로 제공합니다. 서버전은 이전 상태로 되돌아가 다른 명령을 제출할 수 없습니다.

### 선택이 달라져야 하는 구체적 장면

다음은 설명용 가상 상태이며 특정 펫의 실제 스탯이나 실측 결과가 아닙니다.

| 장면 | 가능한 선택과 비용 | 확인하려는 재미 |
|---|---|---|
| Warrior가 HP 20인 Machine과 대치 | ATK/DEF=1, 컬렉션 보정=1, 방어·실드가 없다면 기본기는 약 22~24 피해입니다. 고유기 PP를 소비하지 않고도 마무리할 수 있습니다 | 가장 강한 기술 대신 필요한 만큼만 사용 |
| 내 출전 펫보다 상대가 빠르고, 벤치에 상대의 공개 기술을 잘 버티는 펫이 있음 | 교체하면 이번 공격을 받지만 다음 턴 유리한 기술을 쓸 수 있습니다. 현재 펫으로 버티면 공격 기회는 유지됩니다 | 눈앞의 피해와 다음 턴의 유리함 비교 |
| 상대 HP가 적고 다음 벤치가 건강하며 내 게이지가 10 | 지금 궁극기를 쓰면 처치는 쉽지만 과잉 피해가 됩니다. 일반기로 끝내면 다음 상대에게 궁극기를 쓸 수 있으나 현재 교환의 위험이 남습니다 | 자원을 남기는 판단 |
| 내가 확실히 느리고 두 번의 공격을 견딜 수 있음 | Machine의 레거시 부여로 다음 턴 상대보다 빨라질 수 있는지 비교합니다. 적용해도 여전히 느리다면 피해 기술이 더 나을 수 있습니다 | 상태효과 이름이 아니라 실제 수치에 근거한 선택 |

이 장면들이 튜토리얼 밖 실제 보유 팀에서도 충분히 발생하는지 확인합니다. PP가 줄어든 뒤에만 마지못해 기본기를 사용하는 패턴이라면 역할 분리가 부족한 것으로 판단합니다.

## 엔진과 이벤트 설계

### 상태 전이

```text
준비 → 명령 대기 → 명령 확정 → 양측 행동 처리 → 턴 종료 처리
          ↑                                  │
          └──── 필요 시 강제 출전 선택 ←──────┤
                                             └→ 경기 종료
```

연출은 이 상태 전이와 분리합니다. 엔진이 확정한 이벤트를 재생하는 동안 UI가 입력을 잠그며, 애니메이션 완료 콜백이 피해나 PP를 계산하지 않습니다.

| 모델 | 필수 정보 |
|---|---|
| `ManualBattleState` | 경기 ID, rulesetVersion, catalogVersion, AI 버전, turn, revision, phase, 양 팀, 난수 상태, 결과 |
| `ManualTeamState` | 고정 편성 순서, activeSlot, 팀 게이지, 직전 방어 턴, 시너지 동결값 |
| `ManualCombatantState` | slotID, 펫 스냅샷, 확정 스탯, HP, 기술별 PP, 효과, 행동불가 면역 종료 턴 |
| `ManualEffectState` | effectID, 부여 순번, 부여 턴, 최초 적용 턴, 만료 턴, 실드 잔량 |
| `ManualCommand` | useSkill(skillID), switchTo(slotID), guard, chooseReplacement(slotID), surrender |
| `ManualBattleEvent` | eventID, turn, sequence, actorSlot, targetSlot, eventType, 실제 변경량과 변경 후 값 |
| `ManualBattlePublicState` | 표시 가능한 상태와 합법 명령 목록. 비공개 AI 명령과 난수 상태 제외 |

이벤트 종류는 `turnStarted`, `commandRevealed`, `switched`, `guarded`, `skillUsed`, `ppChanged`, `damage`, `healed`, `effectApplied`, `effectRemoved`, `actionSkipped`, `chargeChanged`, `fainted`, `replacementRequired`, `battleEnded`를 기본으로 합니다. 종료 원인은 전멸·동시 전멸·턴 상한·항복·만료·운영 취소를 구별합니다.

피해 이벤트에는 계산 피해, 실드 흡수량, 실제 HP 감소량, 변경 후 HP를 기록합니다. 상태 이벤트에는 변경 후 기간·실드량을 포함합니다. UI가 현행 카탈로그에서 효과를 재계산하지 않으므로 이후 밸런스 패치에도 과거 로그가 변하지 않습니다.

같은 kind가 양 팀에 존재할 수 있으므로 모든 상태와 이벤트는 side와 slotID로 식별합니다. 한 팀 내 중복 kind 제한은 유지합니다. 기존 로그와 수동 로그는 `formatVersion`으로 구분하고 과거 로그를 새 규칙으로 다시 시뮬레이션하지 않습니다.

### 순수 함수 경계

```text
makeBattle(teamA, teamB, ruleset, seed) -> state
legalCommands(publicState, side) -> commands
chooseAICommand(publicState, policy, aiRandomState) -> command
resolveTurn(state, commandA, commandB) -> nextState + events
resolveReplacements(state, choices) -> nextState + events
publicProjection(state, viewer) -> publicState
```

엔진에서 네트워크, Settings, Keychain, 현재 시각, UI를 읽지 않습니다. 무작위는 전투 판정과 AI 정책을 별도 스트림으로 나누어 AI 평가 횟수가 피해 난수를 바꾸지 않게 합니다. 유효하지 않은 명령은 상태·난수·revision을 변경하지 않습니다. 합법 명령 조회와 피해 미리보기도 난수를 소비하지 않습니다.

Swift에서 로컬 연습전을 먼저 구현한 뒤 동일 모델·처리 순서로 TypeScript에 이식합니다. 처음부터 기존 ATB 엔진을 통합 리팩터링하지 않습니다. 재사용 가능한 상성·기술 메타·스탯 계산을 참조하고, 동일 동작이 검증된 함수만 공통화합니다.

## 저장과 서버 수동전 확장

### 로컬 연습전

명령 대기 또는 강제 출전 대기 상태마다 세션을 원자적으로 저장합니다. 확정한 턴을 저장한 다음 연출을 시작하므로 앱이 꺼져도 이미 실행한 명령이 복제되지 않습니다. 재실행 시 이어하기 또는 포기를 선택할 수 있습니다. 손상된 저장은 읽기 오류로 처리하고 실제 소유·재화를 수정하지 않습니다. Sandbox 실행에서는 기존 `AppEnv`의 격리 경로를 사용합니다.

### 서버 대전의 성격

후속 수동 도전은 다른 유저가 등록한 팀의 스냅샷을 서버 AI가 조종합니다. 상대 유저가 접속하거나 명령을 기다릴 필요가 없습니다. 화면에는 `상대의 등록 팀 · AI 조작`이라고 명시합니다.

수동 도전의 초기 서버 베타에는 Elo, 시즌 점수, 승리 코인을 연결하지 않습니다. 직접 조작한 공격자와 AI 방어자의 성과를 기존 자동 랭크에 섞으면 의미가 달라지기 때문입니다. 이후 경쟁 점수를 도입한다면 수동전 별도 기록으로 설계하고, 수동 도전 때문에 방어자의 기존 자동 Elo를 차감하지 않습니다. 보상 규모와 별도 시즌의 필요성은 이 설계의 구현 전제에 포함하지 않습니다.

### 제안 API 계약

| 작업 | 입력 | 출력·동작 |
|---|---|---|
| start | requestID, 등록 팀 revision | 상대 선정, 스냅샷 동결, 경기 ID·공개 상태 반환 |
| state | battleID, 마지막 수신 eventID | 공개 상태, 이후 이벤트, 만료 시각 반환 |
| command | battleID, requestID, expectedRevision, 명령 | 한 번만 처리한 다음 상태와 이벤트 반환 |
| surrender | battleID, requestID, expectedRevision | 종료 기록 생성, 재호출에도 같은 결과 |

`command`는 강제 출전 선택도 처리하며 현재 phase에서 허용된 명령만 받습니다. 전투 세션마다 revision을 올리므로 같은 턴이라도 강제 출전과 일반 명령을 구분할 수 있습니다. 같은 requestID와 같은 내용은 최초 응답을 재사용하고, 같은 ID에 다른 내용은 충돌 오류로 거부합니다. 오래된 revision은 상태 재조회가 필요한 충돌 응답을 반환합니다.

기존 HMAC 인증 경로를 활용하되 서명에는 battleID, requestID, revision과 정규화한 명령 전체를 포함합니다. 시각 허용 범위만으로 재전송을 막았다고 가정하지 않습니다. 서버는 요청 장치와 세션 소유자, tenant, 계정 상태를 매 호출 검사합니다.

서버는 피해·HP·승패·게이지를 클라이언트에서 받지 않습니다. 등록 팀, 강화 상태, 스킬 해금에서 스냅샷을 구성하고 이후 변경은 진행 중인 경기에 반영하지 않습니다. 기존 `pvp-register-team`은 강화는 서버에서 읽지만 kind·variant·progressUnits는 클라이언트 입력으로 구성합니다. 따라서 수동전 서버 권한을 구현했다고 보유 펫·이로치의 진위까지 해결되는 것은 아닙니다. 유의미한 보상·경쟁 점수 도입 전에 서버가 신뢰할 수 있는 소유·해금 근거를 정해야 합니다.

### 영속성과 동시 요청

세션 상태, 명령 요청 기록, 순서 있는 이벤트, 최종 결과를 영속화합니다. 최소 제약은 세션 ID 유일성, 세션 내 requestID 유일성, 세션 내 이벤트 순번 유일성, 경기당 결과 1개입니다. 참가자의 활성 세션은 하나로 제한해 여러 상대를 미리 열어 결과가 좋은 경기만 고르는 동작을 방지합니다. 계정·상태 기반 활성 세션 조회와 battleID·sequence 기반 이벤트 조회를 인덱스로 지원합니다.

턴 계산은 읽은 revision의 상태로 잠금 밖에서 수행하고, 짧은 트랜잭션에서 revision 조건을 확인한 뒤 새 상태·요청 결과·이벤트를 함께 저장합니다. 동시에 두 명령이 들어오면 하나만 반영됩니다. 충돌한 계산 결과는 폐기하며, 다른 명령으로 자동 재실행하지 않습니다. HTTP 응답이 유실되어도 같은 requestID로 동일 결과를 되돌려줍니다.

종료 턴은 상태 종료와 결과 기록을 같은 트랜잭션으로 확정합니다. 향후 보상을 붙일 경우 경기 ID를 키로 한 지급 원장 또는 outbox를 같은 커밋에 생성하고, 실제 지급의 중복도 그 키로 막습니다. 클라이언트의 결과 화면 표시 여부로 지급을 결정하지 않습니다.

세션 저장소는 클라이언트 직접 쓰기를 허용하지 않습니다. 노출 스키마 사용 시 RLS와 권한을 적용하고, 기존 HMAC 서비스 경로에서 소유자·tenant 검증 후 접근합니다. 난수 상태와 미공개 AI 명령은 공개 응답·클라이언트 로그에 넣지 않습니다. 실제 SQL·마이그레이션은 서버 구현 단계에서 별도 작성합니다.

### 중단과 버전 변경

서버 세션은 생성부터 24시간 동안 이어할 수 있고, 만료 시 `expired`로 닫습니다. 베타에서는 미완료 기록으로 남기고 보상은 없습니다. 향후 경쟁전에서는 만료와 항복을 회피 수단으로 쓰지 못하도록 패배 처리와 일일 한도 소모를 사전 안내해야 합니다. 서버 장애로 운영자가 취소한 경기는 패배·한도에서 제외하는 경로를 별도로 둡니다.

창 닫기와 네트워크 오류를 항복으로 해석하지 않습니다. 재접속 시 서버 상태를 조회하고 마지막 수신 이후 이벤트를 재생합니다. 재시도는 같은 requestID를 사용하며, 로컬 예상 HP를 서버 상태에 덮어쓰지 않습니다.

시작 시 ruleset·catalog·AI 버전을 고정합니다. 진행 중 세션을 지원하는 규칙은 최대 세션 수명과 재시도 유예기간 동안 유지합니다. 서버가 지원 종료한 세션은 운영 취소로 종료하며 신버전 규칙으로 몰래 이어가지 않습니다. 과거 경기 재생은 저장된 이벤트·표시용 스냅샷을 사용합니다.

## 구현 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 규칙 엔진 | Swift 상태·명령·턴·교체·PP·효과·게이지 | 아래 규칙 테스트와 결정성 테스트 통과 |
| 2 수동 연습전 | 기존 편성 연결, 무대 추출, 입력 UI, 로컬 저장 | 560×640에서 명령 접근 가능, 재시작 후 동일 상태 복원 |
| 3 재미 검증 | 대여 튜토리얼, 단순 AI와 전략 AI, 자동 맡기기, 결과 분석 | 사용자 관찰과 밸런스 측정 후 수치 조정 |
| 4 서버 무보상 베타 | TS 이식, 세션 API, 상대 스냅샷, 재접속·멱등성 | Swift·TS 이벤트 일치, 중복·동시 요청·응답 유실 테스트 통과 |
| 5 확장 판단 | 관장 연습 적용 또는 수동 경쟁·보상 검토 | 기존 관장 보상·자동 Elo와의 관계를 별도 결정 |

1~3단계를 첫 구현 범위로 권장합니다. 4~5단계까지 한 번에 구현해야 수동 플레이를 검증할 수 있는 구조로 만들지 않습니다. 코드 변경 이후에는 저장소의 Swift 전체 테스트와 기존 서버 파리티 테스트를 통과시켜 자동전 회귀를 확인합니다.

### 규칙 테스트

- 같은 상태·명령·시드이면 이벤트와 다음 상태가 같습니다. 표시 조회나 설명 팝오버가 결과를 바꾸지 않습니다.
- 잘못된 기술, PP 0, 죽은 펫으로 교체, 현재 펫으로 교체는 상태를 바꾸지 않습니다.
- 교체가 공격보다 먼저이며 공격은 새 출전 펫을 맞힙니다. 교체로 시너지를 다시 계산하지 않습니다.
- 방어가 공격보다 먼저이고 지속 피해는 경감하지 않습니다. 연속 방어 제한을 검증합니다.
- 동속 판정과 턴 도중 SPD 변경이 양 언어에서 같습니다.
- 선공 기절로 후공이 취소되며 후공 PP·게이지를 소모하지 않습니다.
- 행동불가·면역·정화·효과 만료·재부여·슬롯 초과의 순서를 검증합니다.
- 벤치 지속 피해, 벤치 마지막 펫 기절, 양측 동시 전멸과 강제 출전을 검증합니다.
- PP가 교체·재접속으로 회복되지 않고 새 경기에서만 초기화됩니다.
- 게이지는 턴당 최대 2이며 궁극기의 공격 충전과 광역 피격 중복 충전이 없습니다.
- 레인보우가 쓰러져 궁극기를 못 쓰는 경우, 게이지가 턴 도중 찬 경우를 검증합니다.
- 25턴 소모전 진입과 40턴 무승부, 마지막 턴 전멸 우선 판정을 검증합니다.
- 이벤트를 처음부터 재생한 상태와 엔진의 최종 상태가 일치합니다.

### 서버와 UI 테스트

- 같은 요청 2회, 서로 다른 명령 동시 제출, 응답 전 연결 종료, 강제 출전 중 앱 종료를 재현합니다.
- 한 경기 결과·보상 원장이 중복 생성되지 않으며 다른 계정·tenant가 세션을 조회하거나 조작할 수 없습니다.
- AI가 플레이어 명령과 미래 난수를 읽지 않도록 함수 입력과 테스트를 제한합니다.
- 명령 제출 후 버튼 연타·단축키·배속·로그 열기가 추가 명령을 만들지 않습니다.
- 숨김 창의 자동 제출이 멈추고 복귀 시 확정된 턴으로 복원됩니다.
- 긴 기술명, 상태 4개, 잠금 기술, 5마리 파티, 최소 창에서 실제 렌더링을 확인합니다.
- 기존 자동전·관장 재생의 이미지와 HP·게이지 표시 회귀를 확인합니다.

## 재미와 밸런스 평가

초기 내부 플레이테스트는 5~8명 정도의 소규모 관찰로 시작합니다. 통계적 효과를 확정하기 위한 표본이 아니라, 이해하지 못하는 규칙과 반복되는 단조로운 선택을 찾기 위한 단계입니다.

| 평가 질문 | 관찰 또는 측정 |
|---|---|
| 사용자가 상성을 이해하는가 | 안내 없이 타입기와 다른 타입 기술의 차이를 설명하는지 |
| 선택이 반복 클릭으로 끝나는가 | PP가 남은 기술 중 특정 기술만 선택하는 이유, 상태·교체·방어 사용 맥락 |
| 결과를 납득하는가 | 기절·교체 손해·행동불가·궁극기 지연의 원인을 설명하는지 |
| 다시 시도하고 싶은가 | 보상 없이 자발적으로 재대전하며 명령이나 편성을 바꾸는지 |
| 게임이 너무 긴가 | 중앙값 턴·시간, 40턴 도달 비율, 후반 자동 맡기기·포기 시점 |
| 성장이 전략을 압도하는가 | 같은 팀·같은 강화에서 정책 차이와 강화 차이가 각각 승률에 주는 영향 |

시뮬레이션에서는 최소한 같은 성장의 혼합 타입 대 단일 타입, Common 대 고희귀도, 레인보우 유무, 지속 피해 대 회복, 극단 SPD, 방어·교체 반복 정책을 비교합니다. 동일 조건당 1,000개 고정 시드와 좌우 진영 교환을 기본으로 합니다. 항상 강한 기술을 쓰는 정책, 상태를 활용하는 정책, 교체를 활용하는 정책을 분리해 어떤 선택이 실제 가치가 있는지 측정합니다.

초기 경고 기준은 일반 5대5 중앙값 25턴 초과, 턴 상한 도달 5% 초과, 동급 혼합 타입 팀이 단일 타입 팀에 지속적으로 크게 열세인 경우입니다. 기준을 만족해도 재미가 입증된 것은 아니며, 반대로 교체율이 높다는 이유만으로 성공으로 보지 않습니다. 실제로 유저가 의도한 전술을 설명하고 다시 시도하는지가 핵심입니다.

수동전이 귀찮다고 느껴지는 원인이 긴 전투인지, 효과 설명 부족인지, 성장 격차인지 구분한 후 수정합니다. 재화 보상을 올려 재미 검증을 대신하지 않습니다.

## 검토할 주요 선택

다음은 사용자 확정 사항이 아니라 이 초안의 권장안입니다. 구현 전 검토 시 이 항목들을 중심으로 결정하면 됩니다.

| 선택 | 권장안 | 포기하거나 감수하는 점 |
|---|---|---|
| 행동 방식 | 골드식 턴제 | ATB의 SPD 연속 공격 정체성은 수동전에서 달라집니다 |
| 스킬 차별화 | 기존 ID 유지, 타입기 저위력·확정 효과, PP 도입 | 자동전과 수동전의 상세 수치가 달라 별도 설명이 필요합니다 |
| 초기 해금 | 기존 해금 유지, 대여 튜토리얼 | 기본형만 가진 유저의 기술 선택은 제한됩니다 |
| 피해 예측 가능성 | 확률 패링·일반 치명타 제외 | 기존 레인보우의 전투 보너스 일부가 수동전에서는 줄어듭니다 |
| 혼합 팀 구성 | 수동전 시너지 보너스 제한 | 단일 컬렉션을 모은 유저에게 다른 편성을 권하게 됩니다 |
| 첫 공개 범위 | 기존 연습전에 직접 조작 추가 | 기존 랭크전 점수로 즉시 연결되지는 않습니다 |
| 후속 상대 | 유저 등록 팀을 AI가 조작 | 실시간 사람 간 심리전은 제공하지 않습니다 |

첫 검증에서 반드시 답해야 할 것은 기존 스킬·상성으로 기술, 교체, 방어 사이의 선택이 생기는지입니다. 그 답을 얻은 뒤 서버 경쟁과 보상 범위를 정합니다.
