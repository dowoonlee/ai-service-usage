# 아레나 수동 전투 구현과 운영 준비

기준 설계는 [수동 전투 상세 설계](arena-manual-battle.md)입니다. 기존 자동 ATB 랭크·강화·시즌 집계는 변경하지 않습니다.

## 앱 사용 경로

아레나의 연습전에서 `직접 조작 · 수동 연습전`을 엽니다. 팀의 레인보우마다 궁극기 A·B를 선택하고 시작합니다. 펫이 없어도 대여 튜토리얼로 진입할 수 있습니다. 선택 기술·교체·방어는 확인 후 실행합니다. PP, 효과, 게이지는 전투 안에만 존재하며 실제 재화를 사용하지 않습니다.

수동 전투는 `manual-arena-v1.json`에 원자적으로 저장하고 앱 재실행 후 이어갑니다. AppEnv 격리 경로를 사용하며 읽지 못한 저장은 명시적 삭제 전까지 덮어쓰지 않습니다. 같은 시드 재도전은 연습 기록의 중복 승리로 집계하지 않습니다.

현재 배틀 팀은 자체 프리셋 ID가 없으므로 궁극기 선택은 순서 있는 팀 kind 목록별로 저장합니다. 같은 구성으로 돌아오면 복원되며 서로 다른 구성은 독립적입니다. 기존 PartyPreset 저장 구조를 변경하지 않습니다.

## 수동전 규칙

골드식 턴 진행, 교체 우선, 방어, PP, 다음 턴부터 적용하는 행동불가, 2턴 행동불가 면역, 벤치 지속 피해, 팀 궁극기 게이지, 타입별 A·B 궁극기를 구현했습니다. 기존 무작위 패링·일반 치명타는 수동전에 적용하지 않습니다. 25턴부터 소모전, 40턴에 무승부를 판정합니다.

상대는 결정적 공개 상태 기반 AI이며 내 명령 제출 전 행동이 고정됩니다. 자동 맡기기도 동일 규칙과 AI를 사용합니다. Swift와 TypeScript의 수치 상태·명령·이벤트는 12개 궁극기 분기의 전체 경기 fixture로 비교합니다. 표시 이름·문장만 언어별 카탈로그에 따라 다를 수 있습니다.

UI는 확정된 턴의 공격·교체·HP 변경을 순서대로 재생하며 공격 이동과 레인보우 색 순환을 표시합니다. 빠른 연출과 현재 턴 건너뛰기를 지원하고 창을 숨기면 재생과 자동 명령 제출을 멈춥니다. 입력 영역은 최소 창에서도 하단에 고정됩니다. 실제 재미·3~6분 전투 길이 목표는 사용자 플레이테스트 대상입니다.

## 서버 배포 구성

서버 코드는 `supabase/functions/manual-arena/index.ts`와 공유 `manual_battle.ts`입니다. 마이그레이션은 `20261025073446_manual_arena_sessions.sql`입니다. 이 구현 작업에서는 운영 마이그레이션·함수 배포·환경 변수 변경을 실행하지 않습니다.

전투 업적 8종과 칭호를 추가했습니다. [업적 상세 규칙](arena-manual-achievements.md)을 참고하며, `20261025084647_manual_arena_achievements.sql`을 수동전 세션 마이그레이션 다음에 적용해야 합니다. 업적 적립도 신뢰할 수 있는 팀 보유 검증을 전제로 합니다.

배포 시 필요한 순서는 다음과 같습니다.

1. 마이그레이션을 검토·적용합니다. 세션·요청·공식 숙련 기록·검증된 보유 근거 저장소가 추가됩니다.
2. 기존 PvP처럼 HMAC 인증을 사용하도록 `manual-arena` 함수를 JWT gateway 검증 없이 배포합니다. 배포 명령에는 `--no-verify-jwt`가 필요합니다. 저장소의 로컬 `supabase/config.toml`은 Git 제외 파일이므로 배포 플래그를 명시해야 합니다.
3. `MANUAL_ARENA_ENABLED=true`로 서버 도전을 활성화합니다. 기본은 꺼짐이며 앱의 로컬 연습전은 독립적으로 작동합니다.
4. 신뢰할 수 있는 소유 정보에서 `manual_verified_pets`를 채울 경로를 정합니다. 이 테이블은 클라이언트 직접 쓰기를 막고 검증 근거를 필수로 저장합니다.

**기존 pvp_teams를 그대로 복사해 검증된 보유 정보로 취급하면 안 됩니다.** 기존 등록 API의 kind·variant·progressUnits는 클라이언트 제출 값이므로, 신규 서버에서 전투를 계산해도 소유 진위를 증명하지는 않습니다. 팀 전원이 검증된 범위 안에 있을 때만 해당 레인보우 펫에 공식 훈장 적립 자격을 부여합니다. 검증 자료가 없는 경우 서버 대전은 가능하지만 공식 훈장은 적립되지 않는다고 화면에 표시합니다.

서버 대전은 테넌트 내 다른 사용자의 5마리 등록 팀을 AI가 조종합니다. 참가자는 하루 KST 기준 10경기, 활성 세션은 1개, 수명은 24시간입니다. 종료·항복·만료는 기존 Elo나 재화에 영향을 주지 않습니다.

## 공식 훈장

레인보우로 실제 활약한 정상 승리에 1·10·30·100승 훈장을 부여하고, 궁극기 분기별 유효 사용 승리 5회에 A·B 문양을 표시합니다. 공식 기록은 펫 카드·도감·내 트레이너 카드와 카드 내보내기에 표시합니다. 다른 사용자의 트레이너 카드에 내 기록을 표시하지 않습니다.

로컬·대여·동일 조건 재도전은 공식 적립 대상이 아닙니다. 앱의 연습 기록은 별도 미리보기입니다. 공식 집계는 서버 트랜잭션에서 경기 종료와 함께 처리하며 같은 경기·펫은 한 번만 적립합니다. 클라이언트가 보낸 승수·피해·결과로 적립하지 않습니다. 재설치 후 서버 상태 조회로 공식 기록을 다시 받습니다.

공식 기록의 등급과 문양을 표시하고, 마스터 펫이 출전한 승리 화면에는 기존 특수 모션과 홀로 테두리·별 이펙트를 사용합니다. 신규 래스터 에셋은 추가하지 않습니다.

## 검증 명령

```bash
swift test
deno test supabase/functions/_shared/manual_battle.test.ts supabase/functions/_shared/pvp_engine.parity.test.ts
deno check supabase/functions/manual-arena/index.ts
bash scripts/test-manual-arena-db.sh
PREVIEW_OUT_DIR=/tmp/aiusage-manual-previews swift test --filter ScenePreviews.testRenderManualBattle
```

DB 테스트는 전용 임시 PostgreSQL만 사용합니다. postgres 바이너리가 없으면 이미 설치된 `postgres:17.6-alpine` Docker 이미지를 네트워크 없이 실행하고 테스트 종료 후 전용 컨테이너·볼륨을 정리합니다. 운영·기존 로컬 DB에 연결하지 않습니다.

파리티 fixture를 갱신하려면 `MANUAL_PARITY_OUT` 환경 변수로 Swift의 `testExportServerParityVectors`를 실행합니다. 다음에 `scripts/update-manual-parity.py`로 fixture를 정리하고 Deno 파리티를 실행합니다. 새 fixture를 만들기 전 규칙 변경이 의도한 것인지 확인해야 합니다.

## 구현 검증 결과

2026-10-25 업적 추가 후 로컬 검증에서 Swift 테스트 443개 중 34개 시각 검수·fixture 출력 테스트를 제외하고 실패 없이 통과했습니다. Deno 공유 테스트 63개와 신규 Edge Function 타입 체크도 통과했습니다. 별도로 최소 창 560×640의 라이트·다크 편성·명령·업적 화면과 전체 업적 목록을 렌더링해 확인했습니다.

격리 PostgreSQL 테스트에서 활성 세션 동시 생성 차단, 소유자·권한 검사, stale revision·만료 거부, 일일 10회 제한, 재전송 멱등성, 공식 훈장 중복 적립 방지를 확인했습니다. 앱에서는 서버가 명령을 처리한 뒤 응답만 유실된 상황에서 저장·재시작·동일 요청 재시도를 검증했습니다.

업적 테스트에서는 조건별 긍정·부정 사례, 누적 처치 수와 경기 중복 제외, 동일 펫의 A·B 승리, 승리 필수 히든 조건, 계정별 공식 칭호 해금을 확인했습니다. DB에서는 일반 펫 팀의 업적 적립과 미검증 팀·항복 경기 제외, 공식 업적 8종 및 재시도 중복 방지를 검증했습니다.

궁극기 12개 분기의 파리티 시나리오는 모든 턴의 수치 상태와 의미 있는 이벤트가 일치했습니다. 이 시나리오들은 효과·교체 경계 검증용이며 실제 사용자 만족도나 실전 승률을 입증하는 밸런스 표본은 아닙니다. 운영 서버를 대상으로 한 E2E 대전은 수행하지 않았습니다.
